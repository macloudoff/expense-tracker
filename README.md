# Expense Tracker

CLI для учёта расходов с хранением в CSV. Требуются Java 25 и Maven.

## Сборка и запуск

```sh
mvn package
./expense-tracker --help
```

Сборка запускает тесты и создаёт `target/expense-tracker.jar` с зависимостями.
Скрипт использует Java из `JAVA_HOME`, если эта переменная задана, иначе из `PATH`.
В Windows можно запускать JAR напрямую: `java -jar target/expense-tracker.jar list`.

Чтобы вызывать команду без `./`, добавьте каталог проекта в `PATH`:

```sh
export PATH="$PWD:$PATH"
expense-tracker --help
```

## Команды

```sh
expense-tracker add --description "Lunch" --amount 20
expense-tracker add --description "Dinner" --amount 10
expense-tracker list
expense-tracker summary
expense-tracker delete --id 2
expense-tracker summary --month 8
```

ID — постоянное положительное число: оно выводится после добавления и в списке расходов.
Номера не меняются после сортировки или удаления записей и не используются повторно.
Дата по умолчанию — сегодня в `AppConfig.TIME_ZONE`.
Дополнительные параметры добавления:

```sh
expense-tracker add --description "Lunch" --amount 20.50 --date 2020-08-06 --merchant "Cafe"
```

`summary` суммирует все записи. `summary --month 8` — только август текущего года
в часовом поясе приложения. Месяц должен быть от 1 до 12.
Суммы вычисляются через `BigDecimal`; знак `$` используется только при выводе,
модель валюту не хранит.

По умолчанию файл хранится в `data/expenses.csv` относительно рабочего каталога.
Для одинакового хранилища при запуске из разных каталогов задайте абсолютный путь:

```sh
export EXPENSE_TRACKER_DIR="$HOME/.expense-tracker"
```

Каталог создаётся автоматически. Несколько одновременных писателей не поддерживаются.
Коды завершения: `0` — успех, `1` — ошибка хранения, `2` — ошибка команды или данных.

## Числовые идентификаторы

Последний выданный ID хранится рядом с CSV в `expenses.sequence`.
При переносе хранилища копируйте весь каталог, включая этот файл.
После неудачной записи возможны пропуски в нумерации — это нормально.
Одновременные записи из нескольких процессов не поддерживаются.

При первом чтении старого CSV с UUID приложение проверяет все записи,
сохраняет исходный файл как `expenses-uuid-backup-*.csv` и заменяет UUID
номерами 1, 2, … в порядке строк. Остальные поля сохраняются.
Повреждённый файл или смесь UUID и числовых ID отклоняются без перезаписи.
Резервная копия содержит исходные расходы; не публикуйте её.

Новый `Expense` не имеет ID (`getId() == null`). `save()` возвращает отдельный
сохранённый объект с ID, не изменяя исходный:

```java
Expense saved = repository.save(new Expense(description, amount, date, merchant));
saved.setAmount(new BigDecimal("30"));
repository.save(saved);
```

Для повторного обновления используйте возвращённый объект: повторное сохранение
исходного объекта без ID означает добавление нового расхода.
